# Advisories

Every way around the gate or the fence that is found and fixed gets an entry here: what it was, which versions had it, how it was found, and the test that now covers it. Nothing is fixed quietly.

Entries are numbered `SAI-<year>-<number>` and listed newest first. The ones below were found by the project itself before any release; they are written up all the same, because the habit matters more than the audience.

| Id | Fixed in | What it was |
|---|---|---|
| SAI-2026-008 | unreleased, Nov 2026 | Bringing a project in copied your folder into the agent's workspace by name. The workspace is the agent's to write in, so an agent could plant a link under the name being copied to, and your files would be written wherever the link pointed, with your permissions; starting a copy over made the moment easy to hit. The copy is now made in a new folder that is held open and that the agent is shut out of while it is filled, and is given its name only when complete; that last step fails rather than follows a link. Found by an independent read before any release. |
| SAI-2026-007 | unreleased, Nov 2026 | An hourly limit on what may be sent to a place could be exceeded. The first bytes of a connection were never counted (for a plain web request they are the whole request), and bytes were counted after they had been sent, so many connections opened together could each send before any of them was stopped. Everything is now counted before it is sent, and what would go over the limit does not go. Found by an independent read. |
| SAI-2026-006 | unreleased, Nov 2026 | With looking inside on, a second request could be hidden inside the first. Lines in a request end in two characters; some servers also accept the second one alone. The gate checked a request up to the first such lone ending and then passed on everything up to the proper one, so what a lenient server reads as a second request went unchecked: it could name another site at the same provider, reach an address that is switched off, carry a secret past the check for secrets, and leave no line in the log. The same held for a full address written with capitals (`HTTPS://…`), which skipped the check that it names the approved site, and for lengths written with a sign (`+5`). A lone line ending anywhere, a full address that is not a web address, and a length that is not plain digits are now refused. Found by an independent read. Tests: `a_second_request_cannot_hide_behind_a_lone_line_feed`, `a_full_address_is_checked_however_it_is_spelled_and_numbers_are_numbers`. |
| SAI-2026-005 | unreleased, Nov 2026 | A protected app could make macOS show a system prompt on your screen: a keychain dialog ("Keychain Not Found … Reset To Defaults") or the box that asks for your password to allow something. A program inside the fence shares your screen, so such a prompt looks like any other, and an app set on it could ask for your password that way. It also broke ordinary use: Claude Code, saving its sign-in, raised the keychain dialog and waited on it, which is how this was found, in the first real signed-in session. The launch-time profile now refuses the service that shows these prompts; the call fails at once, a program that wanted to save a sign-in keeps it in its own private folder, and the refusal is shown in Activity as "System prompt". Applies to apps that run as their own private user, not to windowed apps, which run as you. Tests: bypass corpus, "Fence: your screen". |
| SAI-2026-004 | unreleased, Nov 2026 | Setup, which runs as administrator, wrote a small note (`README.txt`) into each protected app's workspace and then handed the file to that app's user. The workspace belongs to the protected app, so an app could put a link there under that name and wait for setup to run again: the administrator's write and change of owner would follow the link, creating a file of the app's choosing, owned by the app, anywhere on the computer. From there to full control is a short step. Present on macOS since workspaces were added, and in the new Linux setup. The note is now written as the protected user, never as administrator, and nothing is written if anything already has that name. Found by an independent read of the new code before any release. Test: the Linux end-to-end test plants a link and re-runs setup. |
| SAI-2026-003 | unreleased, Nov 2026 | With looking inside on, a request that merely asked to switch to a web socket made the gate stop reading the rest of that connection, even when the server did not switch. A following request could then name another site or a switched-off address unchecked. Now nothing more is passed on until the server has answered, and what follows is read as what it is. Test: `nothing_more_goes_until_the_server_has_agreed_to_switch`. |
| SAI-2026-002 | unreleased, Nov 2026 | An address inside a place that was switched off could be reached by respelling it (a doubled slash, a dot segment, an escaped letter, different capitals). Addresses are now judged as written and as a forgiving server would read them. Tests: `another_spelling_of_a_switched_off_address_is_refused_too`, seven cases in the bypass corpus. |
| SAI-2026-001 | unreleased, Nov 2026 | Refusals made by the launch-time profile and the packet filter (a program connecting directly instead of through the gate) were enforced but not shown anywhere. They are now read from the system log and appear in the Feed. Not a way around, but a blind spot. |
